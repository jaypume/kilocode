# 5. 风险点清单

> 本文档列出已知的架构风险、边界条件和缓解措施

---

## 风险分类

- 🔴 **高风险**: 可能导致数据丢失、安全漏洞或系统崩溃
- 🟡 **中风险**: 可能导致功能异常或用户体验下降
- 🟢 **低风险**: 边缘情况，影响有限

---

## 1. 并发与竞态 (Concurrency & Race Conditions)

### 🔴 风险 1.1: 任务切换时的状态泄漏

**问题描述**:
用户在任务 A 运行时切换到任务 B，任务 A 的状态可能泄漏到任务 B。

**影响范围**:

- 文件上下文追踪器
- Diff View 状态
- 浏览器会话

**当前缓解措施**:

```typescript
// src/core/webview/ClineProvider.ts:500
async initClineWithTask(task?: string, images?: string[], mode?: string) {
  // 1. 中止旧任务
  if (this.cline) {
    await this.abortTask()
  }

  // 2. 创建新任务
  this.cline = new Task({
    provider: this,
    apiConfiguration: this.api,
    task,
    images,
    mode
  })
}
```

**残留问题**:

- ⚠️ 浏览器会话不会自动关闭（跨任务保持）
- ⚠️ 文件监听器可能未清理

**改进建议**:

1. 在 `Task.dispose()` 中显式关闭浏览器
2. 在 `FileContextTracker.dispose()` 中清理所有文件监听器

**依据**: `src/core/webview/ClineProvider.ts:500-600`

---

### 🟡 风险 1.2: 多个 Webview 实例

**问题描述**:
用户同时打开 Sidebar 和 Tab Panel，可能存在两个 Webview 实例。

**影响范围**:

- 状态同步问题
- 消息重复发送

**当前缓解措施**:

```typescript
// src/core/webview/ClineProvider.ts:142
export class ClineProvider {

	private tabPanel?: vscode.WebviewPanel // Tab Panel

```

**残留问题**:

- ⚠️ 两个 Webview 可能显示不一致的状态
- ⚠️ 用户可能在两个界面同时操作

**改进建议**:

1. 强制只允许一个 Webview 实例
2. 或实现完整的状态同步机制

**依据**: `src/core/webview/ClineProvider.ts:142-200`

### 🟢 风险 1.3: 文件监听器泄漏

**问题描述**:
`FileContextTracker` 为每个追踪的文件创建 `FileSystemWatcher`，如果不清理会导致内存泄漏。

**影响范围**:

- 内存占用增加
- 事件监听器累积

- ⚠️ `Task.dispose()` 中未显式调用 `fileContextTracker.dispose()`

**改进建议**:
在 `Task.dispose()` 中添加：

```typescript
this.fileContextTracker?.dispose()
```

**依据**: `src/core/context-tracking/FileContextTracker.ts:195-200`

## 2. 取消与中止 (Cancellation & Abortion)

### 🔴 风险 2.1: 取消时的资源清理不完整

**问题描述**:
用户取消任务时，某些资源可能未被正确清理。

**影响范围**:

- Diff View 可能残留打开
- 浏览器会话可能未关闭
- 终端进程可能未终止

**当前缓解措施**:

```typescript
// src/core/task/Task.ts:2107
public async abortTask(isAbandoned = false) {
  if (isAbandoned) {
    this.abandoned = true
  }

  this.abort = true

  // 1. 中止当前 API 请求
  this.abortCurrentRequest()

  // 2. 回滚 Diff View
  if (this.diffViewProvider.isEditing) {
    await this.diffViewProvider.revertChanges()
  }

  // 3. 清理资源
  await this.dispose()
}
```

**残留问题**:

- ⚠️ 浏览器会话不会自动关闭
- ⚠️ 终端进程可能继续运行

**改进建议**:
在 `abortTask()` 中添加：

```typescript
// 关闭浏览器
if (this.browserSession.isSessionActive()) {
	await this.browserSession.closeBrowser()
}

// 终止所有终端进程
if (this.terminalProcess) {
	await this.terminalProcess.abort()
}
```

**依据**: `src/core/task/Task.ts:2107-2150`

---

### 🟡 风险 2.2: AbortController 信号未传播

**问题描述**:
某些异步操作可能未监听 `AbortController` 信号。

**影响范围**:

- 文件读取操作
- 浏览器操作
- MCP 工具调用

**当前缓解措施**:

```typescript
// src/core/task/Task.ts:2628
this.currentRequestAbortController = new AbortController()
const streamAbortSignal = this.currentRequestAbortController.signal

// 传递给 LLM API

	...metadata,
	signal: streamAbortSignal,

```

**残留问题**:

- ⚠️ 文件读取 (`fs.readFile`) 不支持 AbortSignal
- ⚠️ Puppeteer 操作不支持 AbortSignal
- ⚠️ MCP 工具调用不支持 AbortSignal

**改进建议**:

1. 使用 `Promise.race` 包装不支持 AbortSignal 的操作
2. 在操作前检查 `this.abort` 标志

**依据**: `src/core/task/Task.ts:2628-2700`

## 3. 权限与安全 (Permissions & Security)

### 🔴 风险 3.1: 内网访问无限制

**问题描述**:
浏览器工具可以访问内网地址，可能泄露敏感信息到 LLM。

**影响范围**:

- `browser_action` 工具
- `@url` 提及

**当前缓解措施**:

- ✅ 用户需要批准 `browser_action launch`
- ❌ 无域名黑名单
- ❌ 无协议白名单

**改进建议**:

```typescript
// 添加域名验证
function isInternalUrl(url: string): boolean {
	const hostname = new URL(url).hostname
	return (
		hostname === "localhost" ||
		hostname.startsWith("127.") ||
		hostname.startsWith("192.168.") ||
		hostname.startsWith("10.") ||
		hostname.match(/^172\.(1[6-9]|2[0-9]|3[0-1])\./)
	)
}

// 在 navigateToUrl 前检查
if (isInternalUrl(url)) {
	const { response } = await this.ask("internal_url_warning", url)
	if (response !== "yesButtonClicked") {
		return
	}
}
```

## 4. 上下文膨胀 (Context Bloat)

### 🔴 风险 4.1: 上下文窗口溢出

**问题描述**:
对话历史过长导致超过模型上下文窗口限制。

**影响范围**:

- API 请求失败 (400 Bad Request)
- 任务中断

**当前缓解措施**:

```typescript
// src/core/context-management/index.ts:150
export async function manageContext(options: ContextManagementOptions) {
	const { totalTokens, contextWindow, autoCondenseContext } = options

	// 1. 计算阈值
	const threshold = contextWindow * (autoCondenseContextPercent / 100)

	// 2. 检查是否超限
	if (totalTokens > threshold) {
		if (autoCondenseContext) {
			// 智能压缩
			const summary = await summarizeConversation(messages, apiHandler)
			return { messages: condensedMessages, didCondense: true }
		} else {
			// 滑动窗口截断
			const result = truncateConversation(messages, 0.25, taskId)
			return { messages: result.messages, didTruncate: true }
		}
	}
}
```

**残留问题**:

- ⚠️ 压缩本身也消耗 token（可能导致递归压缩）
- ⚠️ 单个文件过大时无法压缩

**改进建议**:

1. 限制单个文件的最大 token 数
2. 对大文件自动分块读取
3. 添加压缩失败的降级策略

**依据**: `src/core/context-management/index.ts:150-300`

### 🟡 风险 5.2: Diff 应用失败

**问题描述**:
`apply_diff` 工具的模糊匹配可能失败或匹配错误位置。

**影响范围**:

- 编辑应用失败
- LLM 连续重试
- 用户体验下降

**当前缓解措施**:

```typescript
// src/core/diff/strategies/multi-search-replace.ts:77
export class MultiSearchReplaceDiffStrategy implements DiffStrategy {
	private fuzzyThreshold: number // 默认 1.0 (精确匹配)

	async applyDiff(originalContent: string, diffContent: string) {
		// 1. 解析 SEARCH/REPLACE 块
		const blocks = this.parseDiffBlocks(diffContent)

		// 2. 模糊搜索
		const { bestScore, bestMatchIndex } = fuzzySearch(lines, block.search, startIndex, endIndex)

		// 3. 检查相似度
		if (bestScore < this.fuzzyThreshold) {
			return {
				success: false,
				error: "No match found",
				details: {
					searchBlock: block.search,
					similarity: bestScore,
					threshold: this.fuzzyThreshold,
				},
			}
		}

		// 4. 应用替换
		lines.splice(bestMatchIndex, searchLen, ...block.replace.split("\n"))
	}
}
```

**残留问题**:

- ⚠️ 连续失败 2 次后才显示错误提示
- ⚠️ 错误信息可能不够详细

**改进建议**:

1. 首次失败即显示详细错误
2. 提供最佳匹配位置的上下文
3. 建议使用 `search_replace` 工具作为替代

**依据**: `src/core/diff/strategies/multi-search-replace.ts:77-639`

## 7. 资源管理 (Resource Management)

### 🟡 风险 7.1: Chromium 进程泄漏

浏览器崩溃或异常退出时，Chromium 进程可能残留。

**影响范围**:

- 内存占用
- 端口占用

**当前缓解措施**:

```typescript
// src/services/browser/BrowserSession.ts:208
async closeBrowser(): Promise<BrowserActionResult> {
  if (this.isUsingRemoteBrowser && this.browser) {
    await this.browser.disconnect().catch(() => {})
  } else {
    await this.browser?.close().catch(() => {})
  }
  this.resetBrowserState()
}
```

**残留问题**:

- ⚠️ 异常退出时 `closeBrowser()` 可能未被调用
- ⚠️ 远程浏览器连接断开后无法清理

**改进建议**:

1. 在 Extension 关闭时强制清理所有浏览器进程
2. 使用进程监控确保 Chromium 进程被终止

**依据**: `src/services/browser/BrowserSession.ts:208-225`

### 🟢 风险 7.2: 终端进程未终止

**问题描述**:
长时间运行的命令（如 `npm run dev`）可能在任务结束后继续运行。

**影响范围**:

- 端口占用
- 资源消耗

**当前缓解措施**:

```typescript
// src/integrations/terminal/Terminal.ts:200
async abort(): Promise<void> {
  if (this.process) {
    this.process.kill("SIGTERM")

    // 等待进程终止
    await delay(1000)

    // 强制终止
    if (!this.process.killed) {
      this.process.kill("SIGKILL")
    }
  }
}
```

**残留问题**:

- ⚠️ 子进程可能未被终止（如 `npm run dev` 启动的 webpack-dev-server）

**改进建议**:

1. 使用进程组 ID 终止整个进程树
2. 在 Linux/macOS 上使用 `pkill -P <pid>`

**依据**: `src/integrations/terminal/Terminal.ts:200-250`

**问题描述**:
长时间使用后，任务历史文件可能变得非常大。

**影响范围**:

- 磁盘空间占用
- 加载速度下降

// 任务历史限制
const MAX_TASK_HISTORY = 100 // 最多保留 100 个任务

- ⚠️ 单个任务的消息历史无限制

**改进建议**:

1. 限制单个任务的最大消息数
2. 图像存储为独立文件，消息中仅存储引用
3. 提供手动清理功能

```typescript
// src/utils/safeWriteJson.ts
export async function safeWriteJson(filePath: string, data: any) {
	const tempPath = `${filePath}.tmp`

	// 1. 写入临时文件
	await fs.writeFile(tempPath, JSON.stringify(data, null, 2))

	// 2. 原子性重命名
	await fs.rename(tempPath, filePath)
}
```

**残留问题**:

- ⚠️ 不同进程（VS Code + CLI）同时写入时仍可能冲突

**改进建议**:

2. 实现乐观锁（版本号）

## 10. 性能瓶颈 (Performance Bottlenecks)

### 🟡 风险 10.1: 大文件读取阻塞

**问题描述**:
读取大文件（> 10MB）可能阻塞 Extension Host。

**影响范围**:

- UI 冻结
- 其他操作延迟

**当前缓解措施**:

```typescript
// src/core/tools/helpers/fileTokenBudget.ts:50
export async function validateFileTokenBudget(
	filePath: string,
	availableTokens: number,
	currentTokens: number,
): Promise<BudgetResult> {
	const stats = await fs.stat(filePath)
	const fileSizeBytes = stats.size

	// 估算 token 数 (1 token ≈ 4 bytes)
	const estimatedTokens = Math.ceil(fileSizeBytes / 4)

	if (estimatedTokens > availableTokens) {
		return {
			shouldTruncate: true,
			maxChars: availableTokens * 4,
		}
	}
}
```

**残留问题**:

- ⚠️ 文件读取仍然是同步的（阻塞事件循环）
- ⚠️ 大文件的 token 计数很慢

**改进建议**:

1. 使用流式读取大文件
2. 在 Worker 线程中处理大文件
3. 添加文件大小硬限制（如 50MB）

**依据**: `src/core/tools/helpers/fileTokenBudget.ts:50-100`
