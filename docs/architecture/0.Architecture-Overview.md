## 系统定位

Kilo Code 是一个**多平台 AI 编码助手**，支持：

- ✅ VS Code Extension (主要平台)
- ✅ CLI (Terminal User Interface)
- ✅ JetBrains Plugin (IntelliJ IDEA, WebStorm, PyCharm 等)

核心能力：

1. **Agentic Coding**: 自主规划、执行、验证代码任务
2. **多模态交互**: 文本、图像、浏览器截图
3. **工具编排**: 文件读写、命令执行、浏览器控制、MCP 工具集成
4. **上下文管理**: 智能压缩、滑动窗口、文件追踪
5. **多 LLM 支持**: 50+ 提供商 (Anthropic, OpenAI, Gemini, DeepSeek, 本地模型等)

## 核心技术栈

### 前端

- **UI Framework**: React 18 + TypeScript
- **状态管理**: Jotai (原子化状态)
- **VS Code UI**: `@vscode/webview-ui-toolkit`
- **CLI UI**: Ink (React for CLI)
- **构建工具**: Vite + esbuild

### 后端 (Extension Host)

- **运行时**: Node.js 20.19.2
- **语言**: TypeScript 5.4.5
- **LLM SDK**:
    - `@anthropic-ai/sdk` (Anthropic)
    - `openai` (OpenAI/Azure/DeepSeek/兼容 API)
    - `@google/generative-ai` (Gemini)
- **浏览器自动化**: `puppeteer-core` + `puppeteer-chromium-resolver`
- **HTML 处理**: `cheerio` + `turndown` (HTML → Markdown)
- **MCP**: `@modelcontextprotocol/sdk`

### 基础设施

- **包管理**: pnpm 10.8.1 (Monorepo)
- **构建系统**: Turbo (增量构建)
- **代码解析**: tree-sitter (代码定义提取)
- **Diff 引擎**: `diff` + `fastest-levenshtein` (模糊匹配)
- **IPC**:
    - VS Code: `vscode.postMessage` (Webview ↔ Extension Host)
    - JetBrains: `net.createServer` (Socket RPC)
    - CLI: 进程内通信

## 架构原则

### 1. 单一活跃任务 (Single Active Task)

- 同一时间只有**一个** `Task` 实例运行
- 避免并发竞态，简化状态管理
- 切换任务时自动中止前一个任务

**依据**: `src/core/webview/ClineProvider.ts:142` - `private cline?: Task`

### 2. 栈式循环 (Stack-based Loop)

- 使用**栈**而非递归实现主循环
- 避免调用栈溢出，支持无限轮对话
- 支持重试和错误恢复

**依据**: `src/core/task/Task.ts:2389` - `const stack: StackItem[] = [...]`

### 3. 流式优先 (Streaming First)

- 所有 LLM 交互使用流式 API
- 实时更新 UI，提升用户体验
- 支持中途取消 (AbortController)

**依据**: `src/api/transform/stream.ts` - `export type ApiStream = AsyncGenerator<ApiStreamChunk>`

### 4. 非破坏性操作 (Non-destructive Operations)

- 上下文截断：标记隐藏而非删除
- Diff 预览：先展示再确认
- Checkpoint 系统：支持回滚

**依据**:

- `src/core/context-management/index.ts:66` - `truncationParent` 标记
- `src/integrations/editor/DiffViewProvider.ts:500` - `revertChanges()`

### 5. 多层安全 (Defense in Depth)

- 文件访问：`.kilocodeignore` + workspace 边界检查
- 工具执行：用户确认 + 自动批准限制
- 成本控制：请求数限制 + 成本上限

**依据**:

- `src/core/ignore/RooIgnoreController.ts:89` - `validateAccess()`
- `src/core/auto-approval/AutoApprovalHandler.ts:21` - `checkAutoApprovalLimits()`

## 关键设计决策

### 决策 1: 为什么选择 Puppeteer 而非 Playwright?

**选择**: `puppeteer-core` + `puppeteer-chromium-resolver`

**理由**:

1. 更轻量，仅需 Chromium
2. 自动下载和管理 Chromium 二进制
3. 成熟的 API，社区支持好
4. 支持远程浏览器连接 (用于 Docker/WSL 场景)

**依据**:

- `src/services/browser/BrowserSession.ts:4` - `import { Browser, Page, launch } from "puppeteer-core"`
- `src/package.json:736-737` - 依赖声明

---

### 决策 2: 为什么使用 Anthropic 消息格式作为内部统一格式?

**选择**: `Anthropic.Messages.MessageParam[]`

**理由**:

1. Anthropic 格式更灵活，支持 `ContentBlockParam[]` (文本 + 图像 + 工具调用混合)
2. OpenAI 格式限制较多 (tool_result 仅支持 string)
3. 转换为 OpenAI 格式比反向转换更容易

**依据**:

- `src/api/transform/openai-format.ts:15` - `convertToOpenAiMessages()`
- `src/core/task/Task.ts:177` - `type UserContent = Array<Anthropic.ContentBlockParam>`

---

### 决策 3: 为什么不使用传统的 RAG (Retrieval-Augmented Generation)?

**选择**: 不使用向量数据库和语义搜索

**理由**:

1. 文件内容直接注入上下文更准确
2. 现代 LLM 上下文窗口足够大 (200K+ tokens)
3. 智能压缩 + 滑动窗口足以管理上下文
4. 避免向量搜索的不确定性和延迟

**替代方案**:

- tree-sitter 符号索引 (用于代码定义列表)
- 用户显式 @mentions
- Token 预算管理 (自动截断大文件)

**依据**:

- `src/core/context-management/index.ts` - 无 embedding 相关代码
- `src/services/tree-sitter/` - 仅用于符号提取

## 性能特征

### 响应时间

- **首次 Token**: 通常 < 2 秒 (取决于 LLM 提供商)
- **流式更新**: 实时 (< 100ms 延迟)
- **工具执行**:
    - 文件读写: < 100ms
    - 命令执行: 取决于命令
    - 浏览器操作: 1-3 秒 (含页面加载)

### 资源消耗

- **内存**:
    - Extension Host: 200-500 MB (取决于上下文大小)
    - Webview: 100-200 MB
    - Chromium (如果启动): 200-400 MB
- **磁盘**:
    - 任务历史: ~1-10 MB/任务
    - Chromium 缓存: ~500 MB

### 并发限制

- **活跃任务**: 1 个 (单例模式)
- **API 请求**: 1 个/时 (串行)
- **工具执行**: 1 个/时 (串行)
- **文件监听**: 无限制 (按需创建 FileSystemWatcher)

## 扩展点

### 1. 添加新 LLM Provider

**步骤**:

1. 创建 `src/api/providers/YourProvider.ts`
2. 继承 `BaseProvider` 或 `BaseOpenAiCompatibleProvider`
3. 实现 `createMessage()` 方法
4. 在 `src/api/index.ts:buildApiHandler()` 添加 case

**示例**: `src/api/providers/deepseek.ts`

---

### 2. 添加新工具

**步骤**:

1. 创建 `src/core/tools/YourTool.ts`
2. 继承 `BaseTool<"your_tool">`
3. 实现 `execute()` 方法
4. 在 `src/core/prompts/tools/` 添加工具描述
5. 在 `src/core/task/Task.ts:executeTool()` 添加 case

**示例**: `src/core/tools/SearchReplaceTool.ts`

---

### 3. 集成新 MCP Server

**步骤**:

1. 在 `.kilocode/mcp-settings.json` 添加配置
2. MCP Hub 自动发现和加载工具
3. 工具自动注册到 LLM 系统提示

**依据**: `src/services/mcp/McpHub.ts:connectToServer()`
